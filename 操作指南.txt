================================================================================
  第一章：认识 PatentAgent
================================================================================

  PatentAgent 是一个"会说话的专利分析工具"。

  传统做法：你打开 Excel，筛选数据，画图表，写报告 —— 一个人干所有的活。
  PatentAgent：你跟它说"帮我分析一下碳捕集技术的趋势"，它会自动：
    1. 理解你想要什么
    2. 选择正确的分析方法
    3. 生成交互式图表
    4. 写出分析结论

  它就像一个懂专利分析的助手，你只需要告诉它你要什么。

================================================================================
  第二章：安装与环境配置
================================================================================

  2.1 你需要什么

  - 一台电脑（Mac、Windows 或 Linux 都可以）
  - Python 3.10、3.11 或 3.12（当前官方兼容范围）
  - 8GB 以上内存（视数据量而定）

  2.2 检查 Python 是否已安装

  打开终端（Mac 按 Cmd+空格，输入"终端"；Windows 按 Win+R，输入"cmd"），输入：

    python3 --version

  如果显示 Python 3.10.x、3.11.x 或 3.12.x，说明已安装。
  如果提示"找不到命令"，先去 https://www.python.org/downloads/ 下载安装。

  2.3 安装 PatentAgent

  第一步：把项目文件夹放到你喜欢的位置。

  第二步：打开终端，进入项目文件夹：

    cd ~/Desktop/PatentAgent

  第三步：按锁文件安装 Python 依赖（推荐）：

    uv sync --frozen --all-extras --group dev

  pyproject.toml 是依赖声明源，uv.lock 固定完整版本。requirements.txt 只作为 pip
  兼容导出；不能手工修改。未安装 uv 时可临时使用：

    pip install -r requirements.txt

  第四步：安装前端依赖（首次运行需要）：

    cd frontend
    npm ci
    cd ..

  等待几分钟，看到 "Successfully installed..." 就完成了。

  2.4 一键启动

  最简单的方式——一个命令启动所有服务：

    bash start.sh

  脚本会自动：
    1. 检查依赖
    2. 启动 FastAPI 后端（端口 8000）
    3. 启动 React 前端（端口 5173）
    4. 打开浏览器

  浏览器会自动打开 http://localhost:5173
  后端 API 文档: http://localhost:8000/docs ← 可以在这里直接测试所有接口

  按 Ctrl+C 停止所有服务。

  开发与回归检查：

    uv lock --check
    uv run python -m pytest -q
    cd frontend && npm test -- --run && npm run build

  tests/fixtures/wos_golden 是固定合成数据与 16 个工具的结果漂移门禁。除非有经过审查的
  算法或契约变更，不要更新金样文件。

  2.5 分别启动（高级用户）

  启动后端（终端 1）：

    MCP_INPUT_DIR=./my_patents PATENT_DATA_ROOT=./my_patents uvicorn server:app --host 127.0.0.1 --port 8000

  启动前端（终端 2）：

    cd frontend
    npm run dev

  浏览器打开 http://localhost:5173
  API 文档: http://localhost:8000/docs

  注意：两个终端窗口都不能关！要退出，分别按 Ctrl+C。

================================================================================
  第三章：加载专利数据
================================================================================

  3.1 准备数据文件

  PatentAgent 支持 Web of Science (Derwent) 格式的专利数据。
  文件后缀是 .txt，内容以大写的两字母标签开头（PN、TI、AB 等）。

  如果没有专利数据，可以先用自带的示例数据（在 PatentAgent/my_patents/ 目录下）。

  3.2 加载数据

  启动后，浏览器左边栏显示"数据管理"面板。
  默认使用环境变量 MCP_INPUT_DIR 指定的数据目录。
  如需切换目录，只能选择 PATENT_DATA_ROOT 内的路径，再点击「加载数据」。
  等待片刻，看到专利总量、年份范围、IPC 分类等信息即表示加载成功。

  在"数据管理"下面的输入框里，填上你的专利文件目录路径。
  比如：./my_patents（表示项目目录下的 my_patents 文件夹）

  点击绿色的「加载」按钮。

  等待几秒钟（数据量大可能需要 10-15 秒），看到左侧出现专利总量、时间跨度、
  Top 关键词等信息，就说明加载成功了。

  3.3 数据指纹：确认加载了正确的数据

  加载成功后，侧边栏会显示：
    - 专利总量：目录内专利的总量
    - 时间跨度：最小年份 - 最大年份
    - Top keywords：～
    - Files: 实际读取的文件数

  看一眼 Top keywords，就能确认是不是你想要的那批专利数据。

  3.4 更新数据或切换数据集

  如果要换成另一批专利文件：
    1. 把新文件放到一个新文件夹
    2. 在输入框里填入新路径
    3. 点击「加载」

  首次加载会走完整解析（10 秒左右），以后只要文件没变，缓存命中只需要 0.3 秒。

================================================================================
  第四章：唯一 Web 入口与集成接口
================================================================================

  PatentAgent 只有一个面向用户并持续维护的界面：React Web。

  Web 用户入口
  ────────────
  浏览器打开 http://localhost:5173，三栏布局：
    左栏：数据管理 + LLM 设置
    中栏：Agent 对话（SSE 流式响应，实时看到分析过程）
    右栏：16 个快捷工具（一键执行，结果即时显示）
  适合日常交互式分析。

  REST API 集成接口
  ────────────────
  FastAPI 后端提供标准 REST API + SSE 流式端点。
  可以在 http://localhost:8000/docs 查看 Swagger 交互式文档。
  适合程序化调用、集成到其他系统。

  MCP 可选集成接口
  ────────────────
  启动 MCP 服务器后，Claude Code / VS Code / Cursor 等 AI 客户端
  可直接调用全部 16 个分析工具。
  适合把同一套分析工具接入 AI 原生环境；它不是第二套 PatentAgent 用户界面。

  后续用户操作均以 Web 界面为准，API 和 MCP 章节只面向集成开发者。

================================================================================
  第五章：Agent 对话模式详解
================================================================================

  5.1 连接 AI 大脑

  对话模式需要连接一个大语言模型（LLM）来做智能分析和写作。

  左侧“LLM 设置”卡片显示当前供应商、协议、模型和状态。点击“添加供应商”或
  “切换 / 设置”，进入高级设置：

    1. 从 OpenAI、Claude、DeepSeek、OpenRouter、Ollama、vLLM 或“自定义”预设开始。
    2. 可以修改供应商名称；名称不会决定请求格式，必须正确选择 API 协议：
       OpenAI Chat Compatible、Anthropic Messages 或 DeepSeek Chat。
    3. 检查请求地址和鉴权方式。远程地址必须为 HTTPS；localhost、127.0.0.1、::1
       可以使用 HTTP。本地 Ollama/vLLM 可选择“无鉴权”。
    4. 输入 API Key。切换配置后密钥框始终为空；“已加载”只表示后端内存里仍有凭证。
    5. 手工填写模型 ID，或先点击“获取模型”。获取失败不会清空已填写的模型。
    6. 点击“测试连接”查看分阶段结果；确认通过后点击“保存并连接”。

  三个按钮的区别：
    - 保存：只保存名称、地址、模型和请求参数等非敏感配置，不连接 Agent。
    - 测试连接：真实检查文本、工具选择、工具回传和结构化输出，但不切换 Agent。
    - 保存并连接：完整探测通过后才设为当前供应商；失败不会替换原来可用的 Agent。

  只有普通文本可用、但不能完成 PatentAgent 工具闭环的模型不能激活。探测错误会标明
  认证、地址、协议、模型或能力不兼容类别。生成回答期间不能切换、编辑/删除当前配置
  或断开连接。

  安全说明：API Key 和标记为“敏感”的 Extra Header 只存在后端进程内存，不写入
  SQLite、日志或 API 响应。后端重启后配置仍在，但状态会变为“待输入凭证”。

  注意：如果你不想用 AI 对话模式，可以跳过这一步。
  侧边栏的快捷工具不需要连接 LLM 就能用。

  5.2 开始对话

  在页面底部的输入框里，用自然语言描述你的分析需求。

  举个例子：

    你输入："分析一下这个数据集里近三年的技术趋势"

    Agent 会在几秒钟后回复：
      1. 列出它的分析计划（要执行哪些分析步骤）
      2. 逐个执行分析工具
      3. 显示交互式图表
      4. 写出综合结论

  每次分析，你都能看到：
    - 具体的数字（比如"2022年申请量 13,913 件"）
    - 原生交互式图表（可以鼠标悬停查看数据点）
    - [图表 / 数据] 切换、[原始尺寸 / 适应窗格]、[全屏] 和导出按钮
    - 窄屏默认保持图表可读尺寸，可在图表内部横向滚动，不会强行压缩文字
    - 可展开的工具执行卡片（点击查看详细参数和耗时）

  5.3 追问和深入

  左侧“会话”区域可以新建、切换、重命名和删除会话。会话保存在本地
  .patentagent/sessions.db，刷新网页或重启后端后仍可恢复；API Key 不会写入该数据库。

  Agent 会优先使用当前会话已有的结构化证据回答解释型追问，不重复执行工具。
  修改年份、申请人、IPC 等条件时，只重算受影响的分析；右侧快捷工具结果也会
  自动加入当前会话。例如：
    "IPC 分布方面，H 部（电学）的专利占比是多少？"
    "为什么刚才趋势图在 2021 年出现峰值？"

  如果缺少会实质影响结果的条件，Agent 会先提出一个澄清问题。可以补充条件，
  也可以点击“按默认条件继续”。若 LLM 综合失败，工具结果仍会保留，并显示
  “仅重试总结”按钮，不会重新运行工具。

  5.4 分析计划确认

  有些操作（比如深入读取 5 篇专利的完整信息），Agent 会先展示分析计划，
  让你确认后再执行。这是为了防止浪费 Token（等于浪费钱）。

  看到"请确认或修改分析计划"的提示时：
    - 点击「确认执行」→ 继续分析
    - 点击「修改计划」→ 告诉 Agent 要改什么
    - 点击「取消」→ 放弃这次分析

================================================================================
  第六章：侧边栏快捷工具（不需要 AI，点开就用）
================================================================================

  即使你没连 LLM，也能用侧边栏里的 16 个分析工具。
  每个工具点击后在主窗口即时展示分析结果。

  6.1 数据总览
  ──────────
  点击「数据总览」。
  显示：专利总量、年份范围、IPC 分类、Top 申请人。
  这是分析的第一步，让你了解手里的数据长什么样。

  6.2 趋势分析
  ──────────
  点击「趋势分析」。
  生成一条折线图，横轴是月份，纵轴是申请量。
  能看出专利活动是上升、下降还是平稳。

  6.3 增长趋势
  ──────────
  点击「增长趋势」。
  左侧表格显示每年的申请量、累计总量和同比增长率。
  右侧折线图直观展示年度申请量的变化趋势。
  表格下方自动总结整体趋势（快速增长 / 平稳增长 / 下降）。

  6.4 IPC 热力图
  ────────────
  点击「IPC 热力图」。
  一个彩色矩阵：横轴是年份，纵轴是 IPC 分类（A-H 八个大部）。
  颜色越深，该年份该领域的专利越多。
  一眼看出技术重心在哪个分类、随时间怎么变。

  6.5 词云热点
  ──────────
  点击「词云热点」。
  上面是一个词云（出现越多的词越大），下面是一个柱状图（Top 20 高频词）。
  快速了解专利文档里都在讨论什么技术主题。

  6.6 突发词检测
  ────────────
  点击「突发词检测」。
  显示近期爆发式增长的关键词排名。
  这些词代表了"刚刚兴起、可能会火"的技术方向。

  6.7 逐年关键词
  ────────────
  点击「逐年关键词」。
  分组柱状图，每年一列颜色，展示 Top 关键词在不同年份的频次变化。
  能看到技术热点的迁移轨迹。

  6.8 国家分布
  ──────────
  点击「国家分布」。
  玫瑰图显示各国家/地区的专利申请占比。
  能看出技术主要在哪几个国家布局。

  6.9 合作网络
  ──────────
  点击「合作网络」。
  交互式网络图，节点是申请人/公司，连线表示联合申请。
  可以拖拽、缩放节点。
  注意：WoS 数据通常以单一申请人为主，合作网络可能没有数据。
  如果没有，工具会显示统计信息而非空白。

  6.10 技术路线图
  ─────────────
  点击「技术路线图」。
  可横向浏览的时间轴，每年展示代表性专利；只有内部引证充分时才显示引证路径。
  能看出核心技术沿着时间线的演进。

  6.11 技术功效矩阵
  ───────────────
  点击「技术功效矩阵」。这是最强大的工具之一。

  左侧：热力图矩阵（技术手段 × 技术效果交叉分布）
  右侧：空白点 Top 10 探照灯

  热度高的格子（红色）= 大家都在做的事（红海）
  热度低的格子 = 当前语料中的低共现复核候选；必须核对术语、相关专利和权利要求，不能直接称为蓝海。
  专利数为 0 的格子用金色标记 = 绝对空白 = 创新方向建议

  6.12 专利聚类
  ──────────
  点击「专利聚类」。
  自动将专利文本分为 5 个主题群组，每个群组显示核心关键词。
  能发现数据里隐含的技术子方向。

  6.13 专利价值评估
  ──────────────
  点击「专利价值评估」。
  用 8 个指标给专利评分排名，其中最重要的三个来自引证网络分析：

  SS（共享专业化）= 专利在技术演进路径中的位置，得分越高越核心
  RO（技术深度）= 沿引证链追溯 2 步的专业化程度
  BC（共享度）= 与其他专利共享技术基础的程度

  辅助指标：
  - 同族规模（在多少个国家申请了）
  - IPC 广度（跨几个技术分类）
  - 专利年龄
  - 三方专利（中美欧同时有同族）

  得分最高的专利通常是最核心、最有价值的。
  注：引证指标基于 von Wartburg et al. (2005) 实证研究（r=0.45, p<0.01）。

================================================================================
  第八章：MCP 服务器模式（在 AI 客户端中分析专利）
================================================================================

  8.1 什么是 MCP，为什么用它
  ────────────────────────

  MCP（Model Context Protocol，模型上下文协议）是一种标准化的 AI 工具通信协议。
  通俗地说：

    - 没有 MCP：AI 只能聊天，不能操作外部工具和数据
    - 有了 MCP：AI 可以发现你的工具列表，根据需要自动调用合适的工具

  当你把 PatentAgent 作为 MCP 服务器启动后：
    1. AI 客户端自动发现全部 16 个分析工具
    2. 你只需要用自然语言描述需求
    3. AI 自动选择合适的工具、填入正确的参数、执行分析
    4. 结果直接返回给你，AI 还会基于数据撰写分析结论

  和 Web 用户入口的关系：
    Web 入口 → 在 PatentAgent 浏览器界面管理数据、供应商、会话和完整分析流程
    MCP 集成 → 外部 AI 客户端通过 JSON-RPC 调用同一工具注册表

  8.2 安装 MCP 依赖
  ────────────────

  首先安装 MCP Python SDK：

    pip install mcp

  8.3 启动 MCP 服务器
  ──────────────────

  MCP 服务器有两种运行模式。

  模式一：stdio 模式（推荐）
  ──────────────────────────
  通过标准输入输出与 AI 客户端通信，不占用网络端口，最安全、最简单。

    cd PatentAgent
    python3 mcp_server.py

  启动后，服务器在后台等待客户端连接。终端不会有明显的输出，
  这是正常的——MCP 使用 stdout/stdin 传输数据，日志输出到 stderr。

  模式二：HTTP 模式（远程访问）
  ────────────────────────────
  通过网络端口监听，适合远程客户端或团队共享。

    python3 mcp_http_server.py --port 8000 --host 127.0.0.1

  8.4 环境变量说明
  ───────────────

  你可以通过环境变量配置 MCP 服务器的行为：

  MCP_INPUT_DIR（默认 ./my_patents）
    专利数据文件的目录路径。可以是相对路径或绝对路径。

  MCP_STORE_CACHE_TTL（默认 300）
    数据缓存的秒数。比如设为 600，表示数据每 10 分钟从磁盘重新加载一次。
    如果数据不变，缓存命中几乎不影响性能。

  MCP_LOG_LEVEL（默认 INFO）
    日志级别。可选值：DEBUG / INFO / WARNING / ERROR。
    推荐用 WARNING（只输出警告和错误），因为 DEBUG 会输出大量信息。

  MCP_HTTP_PORT（默认 8000）
    仅 HTTP 模式有效。服务器监听的端口号。

  MCP_HTTP_HOST（默认 127.0.0.1）
    仅 HTTP 模式有效。监听的网络地址。
    127.0.0.1 = 仅本机可访问。配置为 0.0.0.0 或其他非回环地址时，服务会要求
    同时设置 MCP_AUTH_TOKEN，否则拒绝启动。

  MCP_AUTH_TOKEN（默认空）
    MCP HTTP 的 Bearer Token。只在确需非回环访问时设置；客户端请求必须携带
    Authorization: Bearer <token>。stdio 模式不需要此配置。

  MCP_MAX_ITEMS_IN_RESULT（默认 50）
    分析结果中列表数据（如词频列表、搜索列表）的最大条目数。
    限制此值可以防止 AI 客户端上下文窗口被大量数据撑爆。

  设置环境变量的方式：
    # Linux / Mac
    export MCP_INPUT_DIR="/home/user/patent_data"
    python3 mcp_server.py

    # 或者在客户端配置中设置（推荐，见 8.5 节）

  8.5 配置 Claude Code
  ───────────────────

  第一步：在项目根目录（PatentAgent/）下创建或编辑 .mcp.json 文件：

  {
    "mcpServers": {

  8.8 分析结果格式说明
  ──────────────────

  每次工具调用返回两种内容：

  1. 文本数据（Text Content）
     ────────────────────────
     JSON 格式的结构化分析数据。例如：
     {
       "result_type": "yearly_trend",
       "data": [
         {"year": 2018, "count": 13065},
         {"year": 2019, "count": 14132},
         ...
       ]
     }
     AI 客户端会基于这些真实数据生成分析结论。

  2. 嵌入式图表（Embedded Resource，可选）
     ──────────────────────────────────
     HTML 格式的 pyecharts 交互式图表（MIME 类型：text/html）。
     如果你的 AI 客户端支持渲染 HTML，图表会直接显示在对话中。
     如果不支持，AI 仍然可以基于文本数据进行分析。

  8.10 常见问题
  ────────────

  Q：MCP 服务器启动后没有输出，正常吗？
  A：正常。MCP 服务器通过 stdin/stdout 与客户端通信，不在终端显示日志。
     日志信息输出到 stderr。如果需要查看日志，设置 MCP_LOG_LEVEL=INFO。

  Q：工具调用返回错误"年列不存在"？
  A：数据加载失败。检查 MCP_INPUT_DIR 路径是否正确，目录下是否有 .txt 文件。

  Q：能不能同时用 Web 和 MCP？
  A：可以。Web 是用户入口，MCP 是可选集成接口；两者共用相同的工具注册表和引擎层。
     但注意：两个实例各自维护独立的 PatentDataStore，不共享缓存。

  Q：MCP 和 Web 调用的工具代码是一样的吗？
  A：完全一样。MCP 和 FastAPI 都通过相同的 Tool.run() 契约调用运行时注册工具，
     只是上层传输协议不同（JSON-RPC 与 HTTP/SSE）。

  Q：如何在 Claude Code 中确认 MCP 已连接？
  A：在 Claude Code 中输入"列出可用的工具"，如果能列出与 /api/tools 一致的工具
     patent-agent 的工具，说明已连接。

  Q：数据更新后需要重启 MCP 服务器吗？
  A：不需要。MCP 服务器默认每 300 秒（5 分钟）自动检查数据目录是否有变化。
     如果想立即生效，可以重启 MCP 服务器。

  第十章：设置与高级配置
================================================================================

  10.1 请求参数

  高级设置中的“请求参数与专家配置”默认折叠。可设置：
    - 超时 5–300 秒（默认 60）
    - 重试 0–5 次（默认 2）
    - 最大输出 256–32768 Token（默认 8192）
    - 温度 0–2；留空使用服务默认
    - 推理强度 default/low/medium/high/max
    - DeepSeek Thinking mode：auto/enabled/disabled

  10.2 Extra Headers

  每一项填写 Header 名称和值。勾选“敏感”后，值只在测试/连接请求中发送并进入后端
  内存；数据库和重新读取的 API 只返回 Header 名称以及是否已加载。Host、Content-Length、
  Content-Type 等由 HTTP 客户端管理的 Header、重复鉴权 Header、重复名称和带换行的值会被拒绝。

  10.3 Extra Body JSON

  只允许 JSON 对象。编辑器支持即时语法检查、格式化和恢复默认值。以下字段由 Agent
  编排器管理，不能覆盖：model、messages、tools、tool_choice、response_format、
  max_tokens、max_completion_tokens、stream。

  10.4 配置切换和删除

  有未保存修改时，关闭高级设置、切换配置或选择其他预设会要求确认。删除配置也需要
  二次确认。当前已连接配置必须先断开才能删除；删除上次选择的已断开配置后不会自动
  激活其他供应商。

================================================================================
  第十一章：常见问题
================================================================================

  Q：数据加载很慢？
  A：首次加载 68K 条约 10 秒。之后只要文件没变，走缓存仅需 0.3 秒。
     如果文件变了，会自动重建缓存。

  Q：没有 LLM 的 API Key 能用吗？
  A：能。侧边栏从 /api/tools 动态读取工具；无需 LLM，但会按字段能力禁用不可靠工具。
     如果本机已经运行 Ollama/vLLM，也可以新增 OpenAI-compatible 配置并选择“无鉴权”；
     该模型仍须通过完整工具能力探测才能用于 Agent 对话。

  Q：为什么重启后显示“待输入凭证”？
  A：这是安全设计。非敏感配置和上次选择保存在本地 SQLite，但 API Key 和敏感 Header
     只在后端内存中，重启后必须重新输入。

  Q：获取模型失败还能连接吗？
  A：可以。某些兼容服务没有模型列表端点，保留请求地址并手工填写准确的模型 ID，
     然后运行“测试连接”。获取失败不会清空已有模型。

  Q：为什么 AI 的分析结论有时候不准？
  A：AI 严格基于实际分析数据写结论。如果某个维度没有数据
     （比如合作网络为 0），AI 会明确告知"该维度无数据"。
     所有结论中的数字都可以对应到图表中验证。

  Q：为什么合作网络显示"无数据"？
  A：WoS Derwent 数据通常每条专利只有一个申请人，联合申请极少。
     工具会显示具体统计，不会静默失败。

  Q：技术功效矩阵的空白点推荐靠谱吗？
  A：矩阵只把 NOVELTY/描述段作为技术手段代理，把 USE/ADVANTAGE 作为效果代理。
     零或低共现仅是相关专利人工复核候选，不能直接称为“绝对蓝海”。

  Q：如何添加自己的分析工具？
  A：1) 在 engine/ 写计算函数
     2) 在 tools/ 封装为 Tool 子类
     3) 在 tools/__init__.py 导入
     Tool 自动注册，侧边栏自动出现。

  Q：程序启动不了？
  A：检查 Python 版本 >= 3.10，运行 pip install -r requirements.txt。
     如果还有问题，查看终端的错误信息。

  Q：怎么停止程序？
  A：回到终端，按 Ctrl+C。
