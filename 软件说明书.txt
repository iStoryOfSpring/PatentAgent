================================================================================
  一、产品概述
================================================================================

  PatentAgent v2.0 是一个基于大语言模型（LLM）的智能专利分析系统。
  提供 React Web 界面、FastAPI REST API、MCP 标准服务器三种交互方式。

  核心能力:
    - Web 界面: React + TypeScript，SSE 流式响应，三栏布局
    - REST API: 数据、工具、Agent、会话与报告端点 + Swagger /docs 自动文档
    - MCP 协议: Claude Code / VS Code / Cursor 直接调用 16 个工具
    - Agent 对话: 自然语言提问，LLM 自动选择工具链，流式返回结论
    - 战略建议: 跨工具关联推理 + 7 种建议类型（研发投入/专利申请/风险规避等）
    - 自适应规划: 根据中间结果动态调整分析步骤，追加或跳过工具
    - 全维度分析: 16 个专业工具（趋势/聚类/功效矩阵/价值评估/技术路线图/竞对演化等）
    - 极速加载: Parquet 列式缓存 (186 MB vs 原 pickle 439 MB)，加载 <1s

  适用场景:
    - 专利全景分析（技术趋势、构成、分布）
    - 竞争对手专利布局对比
    - 技术创新机会发现（功效矩阵 + 空白点探照灯 + 聚类）
    - 专利价值评估与排名（SS/RO/BC 引证指标 + 辅助维度）
    - 技术路线图绘制（引证 + 功效 + 价值 + 时间四维）
    - 侵权风险排查（FTO 检索 + 权利要求分析 + 规避设计建议）

  四、快速入门
================================================================================

  1. 启动应用（bash start.sh）
  2. 左侧栏"数据管理"→ 确认数据目录 → 点击"加载数据"
  3. 左侧栏"LLM 设置"→ 选择供应商 → 填入 API Key → 点击"连接"

  八、核心算法详解
================================================================================

  8.1 核心专利识别 —— 三层复合评分算法

  PatentAgent 使用三层复合算法识别核心专利，最核心的指标来自
  von Wartburg et al. (2005) 的实证研究。

  第一层：PageRank 引证网络排名
  ─────────────────────────────
  构建专利引证有向图（节点 = 专利号，边 = A引用B → A→B），
  使用 Google PageRank 算法（α=0.85, 最大100次迭代）计算每件专利
  在网络中的结构重要性。同时统计入度（被引次数）和出度（引用他人次数）。

  局限性：WoS Derwent 数据只有后向引用（CR字段），没有前向引用。
  因此 PageRank 仅供参考，不作为核心指标。

  第二层：共享专业化（Shared Specialization, SS）
  ─────────────────────────────────────────────
  文献来源：von Wartburg, I., Teichert, T., & Rost, K. (2005).
  "Inventive progress measured by multi-stage patent citation analysis."
  Research Policy, 34(10), 1591-1607.

  SS 由两个子指标合成：

  a) 可达性出度（Reachability Out-degree, RO）— 衡量技术深度
     公式：RO = Σ (1/N_A × 1/N_B_i)  沿长度为2的引证链
     专利A引用了N篇专利 → 每篇权重 = 1/N
     被引专利B又引用了M篇 → 每篇权重 = 1/M
     RO累积了A→B→C两步链路上的所有权重
     物理含义：该专利的技术知识沿引证网络传播了多远
     最终取 log(RO + 1) 修正长尾分布

  b) 书目耦合度（Bibliographical Coupling, BC）— 衡量技术广度
     公式：BC(A,D) = 2 / (N_A + N_D)  对所有与A共享引用的专利D
     使用倒排索引在O(N)时间内完成全网扫描
     物理含义：有多少其他专利和该专利站在同一个"技术肩膀"上

  c) SS = RO + BC
     论文实证结果：
     ┌────────────────────┬──────────────────┬────────┐
     │ 指标                │ 与专家评分相关系数  │ p值    │
     ├────────────────────┼──────────────────┼────────┤
     │ 简单被引次数         │ r = -0.09        │ 无关    │
     │ 共享专业化 SS        │ r = 0.45         │ <0.01  │
     └────────────────────┴──────────────────┴────────┘
     该相关性只来自可变气门领域 107 个专利族，不能推广为通用专利质量或
     财务价值结论。混合公开局或网络不闭合时，SS 不进入价值筛查分。

  第三层：按数据门禁动态启用的稳健百分位筛查
  ──────────────────
  将 SS 与5个辅助商业指标结合，归一化到 [0,1] 后加权求和，得分 0-100：

  默认候选维度：SS 35%、同族规模 20%、IPC 广度 15%、公开年龄 10%、
  US+EP+JP 三方族 10%、后向参考数 10%。所有指标按数据集内百分位归一化；
  SS 已包含 RO+BC，不重复加入 RO、BC。同族覆盖低于 50% 时同族规模和三方族
  退出；引证复现门禁不通过时 SS 退出，其余权重重新归一。

  综合评分公式：
    Score = Σ (normalized_indicator_i × weight_i) × 100
  ────────────────────────────────────────────────────────

  8.2 近期增长词 —— 平滑文档频率窗口对比

  这是工程近期增长分数，不是 Kleinberg Burst，也不借用其算法名称。

  方法：将全部年份按时间排序，等分为"前半窗口"和"后半窗口"。
  对每个关键词分别计算早/晚期标准化频率（每百万词），
  然后计算突发指数：

    recent_growth = smoothed_recent_document_frequency /
                    smoothed_history_document_frequency

  使用文档频率、最小支持度与加性平滑，降低单次出现的伪热点。
  该指标是工程“近期增长分数”，不是 Kleinberg Burst。

  此方法适用于 > 3 年的数据集。年份不足时自动跳过。

  ────────────────────────────────────────────────────────

  8.3 专利聚类 —— TF-IDF 空间 K-means + 展示降维

  Step 1 — TF-IDF 向量化（max_features=500）
    将专利标题+摘要转为 TF-IDF 加权词向量矩阵 (n_docs × 500)

  Step 2 — K-means 直接在 TF-IDF 空间聚类（n_init=10）
    用户不指定 k 时，在受控范围内按 cosine silhouette 选择。

  Step 3 — TruncatedSVD 降维到 2D
    仅用于可视化，不作为聚类输入。

  Step 4 — 簇中心关键词提取
    计算每个簇在 TF-IDF 空间中的质心向量，
    取权重最高的10个特征词作为该簇的代表关键词

  文献参考：Manning, Raghavan & Schütze (2008)
  "Introduction to Information Retrieval", Ch.16-17

  ────────────────────────────────────────────────────────

  8.4 Derwent 摘要代理功效矩阵

  Step 1 — 关键词共现矩阵构建
    从 NOVELTY/DETAILED DESCRIPTION 提取技术手段代理词，
    从 USE/ADVANTAGE 提取用途与效果代理词，并分别应用文档支持门槛。
    构建 functions × effects 的共现计数矩阵。

  Step 2 — 密度热点/空白点检测
    热点识别：矩阵中密度 > 均值+1σ 的单元格标记为"红海"
    低共现候选：按专利数升序排列，但零共现必须经术语质量与相关专利人工复核

  数学基础：Co-occurrence analysis in technology mining
  (Porter & Cunningham, 2005, "Tech Mining")

  ────────────────────────────────────────────────────────

  8.5 公开增长概况 —— 累计公开量 + 年增长率（不判定生命周期）

  v1.4 重构：原 Logistic S 曲线拟合在少量数据点上无统计意义
  （3参数模型，2自由度，任意5个点都能"拟合"）。

  替换为诚实的数据展示：
    - 逐年申请量
    - 累计申请量（C(t) = Σ counts_t）
    - 年同比增长率（(C_i - C_{i-1}) / C_{i-1}）
    - 仅报告公开量增长方向；不得按 CAGR 自动命名萌芽/成熟/衰退阶段

  ────────────────────────────────────────────────────────

  8.6 相关专利筛查 —— TF-IDF 词项相似度检索

  嵌入策略（优先级从高到低）：
    1. OpenAI text-embedding-3-small（需 API Key）
    2. Sentence-Transformers paraphrase-multilingual-MiniLM-L12-v2（本地）
    3. TF-IDF 降级方案（零外部依赖）

  检索流程：
    1. TF-IDF 词项余弦相似度 top_k × 3 候选（不是神经语义嵌入）
    2. 结构化过滤（年份、IPC、申请人）
    3. 关键词匹配加权融合

  返回专利摘要（PatentSummary，不含 claims/description/citations）
  防止 Token 爆炸。深读通过 read_patent_details 按需加载（最多5篇）。

  ────────────────────────────────────────────────────────

  8.7 申请人合作网络 —— 组合边权重

  对每条专利的申请人列表（分号分隔），取所有两两组合 (n choose 2)，
  计数作为边权重。例如：一条专利的申请人为"A;B;C"，生成三条边：
  A-B, A-C, B-C，每条权重 +1。

  可视化通过 pyecharts 力导向图（最多50个节点），节点大小反映
  连接数（度中心性），边粗细反映联合申请次数。

  文献参考：Newman (2010) "Networks: An Introduction"

  ────────────────────────────────────────────────────────

  8.8 IPC 趋势分析 —— Year × Section 矩阵

  构建 years × IPC sections（A-H 八大部）的专利计数矩阵。
  计算每个 IPC 分类的增长率 = (最后一年 - 第一年) / 第一年。
  通过 pyecharts HeatMap 可视化，颜色深浅反映专利密度。

  8.9 复合短语提取 —— 统计合并算法 (Tseng 2007 §3.3)
  ─────────────────────────────────────────────

  来源: Tseng, Lin & Lin (2007) "Text mining techniques for patent analysis"
        Information Processing and Management, 43, 1216-1247.

  算法:
    将专利文本分词后统计所有相邻词对(bigram)的出现频率。
    对每个词对计算 Stickiness(黏合度):
      Stickiness(A,B) = freq(A+B)² / (freq(A) × freq(B))
    若 Stickiness > 阈值(默认0.5) → 合并为复合短语 (如 solid_electrolyte)

  与现有 jieba 单字分词的对比:
    jieba 输出: solid, state, electrolyte (三个无关单字)
    复合短语输出: solid_electrolyte (一个完整概念)
    论文验证: 复合短语在专利分析中比单字精确度高 3-5 倍

  此算法无词典、无语料依赖，适用于任何语言的非结构化文本。

  8.10 聚类标题生成 —— CC0.5 改进相关系数 (Tseng 2007 §4.4)
  ─────────────────────────────────────────────

  算法:
    CC(t,C) = (TP×TN-FP×FN) / sqrt((TP+FP)(TP+FN)(TN+FP)(TN+FN))

  TP/FP/FN/TN 按“文档是否包含术语”计算。CC0.5 只保留在簇内超过 50%
  文档出现的术语，再按相关系数排序。这与旧版概率调和公式不同。

  8.11 竞争对手技术演化 —— IPC 画像描述性指标
  ───────────────────────────────────────────────────────

  证据等级: 工程启发式。不是 Tang et al. (2012) PatentMiner 的 DICT/PBC/HBC。

  三个指标:

  IPC profile cosine shift = 1 - cosine(IPC_profile_t, IPC_profile_{t-1})
    衡量相邻年份技术重心的移动速度。值越大 = 转型越快。

  IPC entropy = - Σ p_i × log(p_i)
    衡量技术多元化程度。值越大 = 技术跨度越广。

  dominant IPC share = max(IPC_share)
    衡量核心领域的集中度。值越大 = 越专注于单技术方向。

  输出: 对 Top N 申请人生成年度演化报告，含每年 Top IPC、转型速度、多元化趋势。

  8.12 专利摘要提取 —— 加权句子评分 (Tseng 2007 §3.2)
  ─────────────────────────────────────────────

  算法:
    Score(S) = 0.35 × keyword_density + 0.25 × title_match
             + 0.20 × cue_phrase      + 0.20 × position

    其中:
      keyword_density = Σ(tf_w / avg_tf) / |S|    句子中关键词的TF密度
      title_match = |S ∩ title_words| / |title_words|  标题词重合度
      cue_phrase = 1 (含专利特征短语) / 0 (不含)
      position = 1.0(首句) / 0.8(首段) / 0.5(其他)

  论文验证: 提取式摘要保留了85%+的核心信息量, 长度仅为原文的15%。

================================================================================
  七、Agent 对话模式
================================================================================

  对话流程:
    1. 用户输入自然语言 → POST /api/agent/chat（SSE 流式）
    2. Agent 理解意图 → 匹配 4 大分析工作流之一
    3. 自适应执行 → 每步工具执行后评估是否调整计划
    4. 跨工具关联 → 趋势×IPC 关联、聚类×价值关联、矩阵×突发词关联
    5. 战略建议生成 → 研发投入、专利申请、风险规避、人才挖掘等 7 种建议

  4 大分析工作流:
    技术全景挖掘: 总览→趋势→生命周期→IPC→词云→突发词→功效矩阵→聚类→国家分布
    初步相关专利筛查: 总览→TF-IDF 检索→IPC→首个公开局→记录读取→价值筛查
    竞争对手监控: 总览→趋势→IPC→合作网络→功效矩阵→价值评估→聚类→国家分布
    资产评估运营: 总览→价值评估→聚类→国家分布→IPC→功效矩阵
